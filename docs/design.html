1. Architecture at a glance

The stack and the scenario never change between stages; only what sits between them does. A scenario is written once (Scenario Model), the runtime turns it into actors, vehicle motion and sensor data, and one gateway delivers that data to the stack (Stack Interface Gateway). CSTI has no safety role: the stack's own fault detection, state machines and safety interlock keep the vehicle safe, and CSTI stops injecting when the stack reports a fault. Everything is recorded (Recording & Replay).

7. Test tracking

Simulink Test Manager runs each RoadRunner scenario and its variants against the models in MiL and PiL, and its test cases are linked to the requirements in Requirements Toolbox, so every run updates each requirement's pass or fail status. HIL and vehicle results join the same view as result files, and scenes rebuilt from real map data rerun the same tests. The requirements page explains how the team's Excel sheet stays in sync.
