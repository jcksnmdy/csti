2. Change scenarios

Add a new simulator

A new sensor simulator arrives.

ComponentImpactWhat
Test OrchestratorConfiguration onlyNew run-profile entry
Backend AdaptersChangesNew adapter

Unchanged: 12 of 14 components, the stack and every scenario.

Only a new adapter is written. Scenarios, the contract and the stack are untouched.

Requirements: New backend = new adapter only, Vendor dependencies only in adapters, Three simulation backends · Decisions: Adapter pattern, CSTI owns actor behavior

Add a new sensor type

The vehicle gains a new sensor.

ComponentImpactWhat
Test OrchestratorConfiguration onlyFidelity setting
Backend AdaptersChangesRaw output, if wanted
Sensor Abstraction LayerChangesNew sensor model
Stack Interface GatewayAdditions onlyNew topics added; nothing existing changes
Recording & ReplayConfiguration onlyTopic list
Monitoring & Operator ViewChangesOptional display

Unchanged: 8 of 14 components, the stack and every scenario.

The contract grows by addition, so the stack's existing inputs are untouched. Scenarios do not change.

Requirements: New sensor = add-only change, Two sensor fidelity levels (object level and raw), Same topics as real sensors, /virtual/ mirror · Decisions: Frozen stack contract, Object-level injection in ViL

Support a second vehicle

A second vehicle wants to use CSTI.

ComponentImpactWhat
Scenario ValidatorConfiguration onlyVehicle limits
Sensor Abstraction LayerConfiguration onlySensor mounts
Ego-State BridgeConfiguration onlyVehicle model and frames
Stack Interface GatewayConfiguration onlyTopic map

Unchanged: 10 of 14 components, the stack and every scenario.

Everything vehicle-specific lives in a vehicle profile. Scenarios run unchanged because they are written relative to the road and the ego vehicle.

Requirements: Same scenario in every stage, Stage selection by configuration, Portable across nodes · Decisions: Simulator-agnostic scenario format, Frozen stack contract

Move ViL from a closed course to public roads

Someone proposes vehicle tests in normal traffic.

ComponentImpactWhat
Test OrchestratorRefusesNo public-road run profile exists

The design refuses this, because a phantom vehicle that causes hard braking could cause a real collision with traffic nobody simulated. Allowing it would need a different system and regulatory approval, not a CSTI change.

Requirements: No pop-in actors, Closed course with safety driver · Decisions: CSTI has no safety authority
