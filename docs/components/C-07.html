Sensor Abstraction Layer

Design › Sensor Abstraction Layer

ResponsibilityProduce simulated sensor data in the stack's own formats, at object level or raw.
Tool category«tool» Sensor model library
OwnerMember 4
GroupSimulation runtime
DeploymentDesktop in MiL; on the bench and vehicle, a separate Intrepid data logger
ProvidesSynthetic sensor frames
RequiresBackend adapter interface, Actor states, Ego state, Clock and sync health

Description

Object level gives radar object lists, V2X messages and object lists for every actor in view, optionally with realistic noise and misses. Raw comes from AURELION: camera images (rectilinear or fisheye lens), radar raw data or detections, LiDAR point clouds with reflectivity, and ultrasonic echoes. Fusion stays in the stack.

Key behaviors

  • Fidelity is chosen per sensor per run.
  • A new sensor type is a new model, not a change to existing ones.

Stage variation

Ground truth in controls MiL and PiL; raw and object level from AURELION in perception MiL and PiL; object level only in HIL and ViL.

Failure behavior

Late frames are dropped and counted; sustained lateness stops injection.

Requirements satisfied (8)

  • Two sensor fidelity levels (object level and raw) (primary)
  • Same topics as real sensors, /virtual/ mirror (supporting)
  • Real-pose ego and placement (ViL) (supporting)
  • New sensor = add-only change (primary)
  • Portable across nodes (supporting)
  • Injection latency limit (supporting)
  • Deterministic MiL runs (supporting)
  • Full rate with many actors (supporting)
