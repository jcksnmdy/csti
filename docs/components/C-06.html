Trigger Engine

Design › Trigger Engine

ResponsibilityFire the scenario's events (actor maneuvers, faults, end of test) when their conditions are met.
Tool category«tool» OpenSCENARIO storyboard triggers
OwnerMember 3
GroupSimulation runtime
DeploymentDesktop in MiL; on the bench and vehicle, a separate Intrepid data logger
ProvidesActor commands, Fault schedule
RequiresParsed scenario, Actor states, Ego state, Clock and sync health

Description

Conditions can be time, actor state or ego state, such as distance or time gap. On the vehicle it refuses to place a new actor too close in front of the car.

Key behaviors

  • Fires within one update of the condition becoming true.
  • Every fired trigger is recorded.

Stage variation

Identical in every stage; the too-close guard is active only in ViL.

Failure behavior

A broken trigger stops the run; triggers are never skipped silently.

Requirements satisfied (5)

  • Time / actor / ego triggers (primary)
  • Sensor fault injection (supporting)
  • Portable across nodes (supporting)
  • Deterministic MiL runs (supporting)
  • No pop-in actors (primary)

Related decisions

  • CSTI owns actor behavior
  • Validate before the run
