Stack Interface Gateway

Design › Stack Interface Gateway

ResponsibilityBe CSTI's only way into the autonomy stack.
Tool category«tool» ROS 2 node with a frozen topic contract
OwnerMember 4
GroupStack boundary
DeploymentNext to the stack
ProvidesStack interface contract
RequiresSynthetic sensor frames, Stack status

Description

It publishes virtual data on the same input topics fusion already reads, marked as virtual and copied to a logging topic. Real sensor data never passes through it. The topic contract only ever grows, so the stack is never broken by a CSTI change. It publishes only while a run is active and the stack reports no fault.

Key behaviors

  • Replayed runs go through the same path as live ones.

Stage variation

Same topics in every stage; on the vehicle it publishes alongside the real sensors.

Failure behavior

If it stops, virtual data simply stops; real data and the stack's safety chain are unaffected.

Requirements satisfied (9)

  • Same scenario in every stage (supporting)
  • Same topics as real sensors, /virtual/ mirror (primary)
  • Replay any run in MiL (supporting)
  • New sensor = add-only change (supporting)
  • Injection latency limit (supporting)
  • Real sensor data never altered (primary)
  • Stop injection on stack fault or override (primary)
  • Stop injection on operator command (supporting)
  • CSTI cannot affect the stack's safety chain (primary)

Related decisions

  • Frozen stack contract
  • Injection on fusion's existing topics
  • Stop injecting on a stack fault
