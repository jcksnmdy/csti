Time & Sync Service

Design › Time & Sync Service

ResponsibilityBe the single clock for each stage.
Tool category«tool» Time synchronization service
OwnerMember 5
GroupSimulation runtime
DeploymentDesktop in MiL; on the bench and vehicle, a separate Intrepid data logger
ProvidesClock and sync health
RequiresRun control

Description

MiL and PiL use simulated time, so desktop runs are repeatable. In co-simulation the AURELION Setup block's synchronization pipeline keeps Simulink and AURELION in step at the configured update rate (20 ms in the team's setup). HIL uses the real-time target clock; ViL uses GNSS time, the same base the ingest middleware uses.

Key behaviors

  • Reports clock offsets so timing problems are caught.

Stage variation

Simulated time in MiL and PiL, real time in HIL and ViL.

Failure behavior

Losing the time reference stops injection.

Requirements satisfied (5)

  • Replay any run in MiL (supporting)
  • Injection latency limit (supporting)
  • Clock offset limit (primary)
  • Deterministic MiL runs (primary)
  • Faithful replay timing (supporting)

Related decisions

  • One clock master per stage
