Actor Manager

Design › Actor Manager

ResponsibilityOwn the motion of every simulated vehicle, motorcycle and pedestrian, independent of any simulator.
Tool category«tool» RoadRunner Scenario actors, sent to AURELION as fellow vehicles
OwnerMember 3
GroupSimulation runtime
DeploymentDesktop in MiL; on the bench and vehicle, a separate Intrepid data logger
ProvidesActor states
RequiresActor commands, Ego state, Clock and sync health

Description

Actors follow routes, change lanes, follow scripted paths or hold a gap relative to the ego vehicle. Ego-relative behaviors keep vehicle tests meaningful, because a real car never drives the same path twice. Seeded randomness makes desktop runs repeat exactly.

Key behaviors

  • Same actor motion on every simulator.
  • Handles the full actor count at the base rate.

Stage variation

Identical in every stage; in ViL actors follow the real vehicle.

Failure behavior

Missed updates are reported; if sustained, injection stops.

Requirements satisfied (6)

  • Backend-independent actor state (primary)
  • Real-pose ego and placement (ViL) (supporting)
  • Portable across nodes (primary)
  • Injection latency limit (supporting)
  • Deterministic MiL runs (supporting)
  • Full rate with many actors (primary)
